### 0.1 模块与数据流

```

│ 叠加层   │           │  应用入口    │◀────────────────────│              │
│（画布 +  │           │（帧流水线）  │   InteractionFacts   └──────────────┘
│  帧循环）│           │              │
│          │           │              │  时间 + IconUpdate + InteractionFacts  ┌──────────┐
│          │           │              │──────────────────────────────────────▶│ Emotion  │ 情绪引擎：这一帧画哪些脸
```

- 五个功能模块（IconBridge / Overlay / Faces / InputSense / Emotion）**只依赖 DDMCore**，彼此互不依赖、互不知道对方存在。
- 只有应用入口 DontDeleteMe 认识所有模块，把它们接起来（`Sources/DontDeleteMe/FramePipeline.swift`）。
- 全局暂停开关 `PauseSwitch.shared` 各模块都可以读（§9）。

### 0.2 一帧里发生的事

叠加层拥有帧循环。每一帧它回调应用一次，应用按下面的顺序做完所有事：

1. 取出两帧之间图标桥上报的内容，合并成一份 `IconUpdate`；没有上报就是"没变化"。
2. 把「时间 + `IconUpdate`」喂给交互感知，得到 `InteractionFacts`。
   如果事实里带着 `wantsIconRefresh`，就调图标桥的 `refreshNow()`。
3. 把「时间 + `IconUpdate` + `InteractionFacts`」喂给情绪引擎，得到要画的脸（`FacePlacement` 清单）。
4. 把每张脸变成一个画布项（`OverlayItem`）：外扩多少问表情绘制者；表情没变、循环小动画也没到刷新时刻，就沿用旧的内容版本号。
   "表情没变"包括一种省电的情形：**只有视线目标变了，而眼珠的落点几乎没动**（鼠标在远处挪动时就是这样，变化不到整段行程的 2%，
   相当于不到十分之一点）——这时也沿用屏幕上已有的画面。比较的对象始终是屏幕上那张图对应的表情，所以偏差不会攒起来。
5. 把各方的省电信号合成一个（取最紧的），连同画布项清单一起返回给叠加层。
6. 叠加层比较新旧清单：没变的不动，只是位置变了的移动，内容变了的回调应用重画——应用再把它交给表情绘制者。

## 1. 坐标约定

代码：`Coordinates.swift`、`Coordinates+System.swift`、`Geometry.swift`

### 1.1 全局坐标——全工程唯一的"通用语"

- **原点**：主屏（带菜单栏的那块屏）的**左上角**。
- **方向**：x 向右，**y 向下**。
- **单位**：点（不是像素）。Retina 屏上 1 点 = 2 像素。
- **多显示器**：其它屏按排列关系落在同一个平面上，坐标可以是负数。例如主屏左侧的外接屏，x 是负的。

它和这些系统来源是同一套坐标，数值可以直接用、不必换算：访达的 desktop position、`CGDisplayBounds`、
`CGWindowListCopyWindowInfo` 的窗口边界、`CGEvent.location`。

**规定**：DDMCore 里出现的所有 `CGPoint` / `CGRect`，除非名字里写明 `appKit` 或 `local`，一律是全局坐标。
唯一的例外是 `FaceState.gazeTarget`，它是相对图标中心的位移（§4）。

### 1.2 另外两套坐标，只在边角处出现

| 坐标 | 原点 | y 方向 | 谁会用到 |
|---|---|---|---|
| AppKit 坐标 | 主屏**左下角** | 向上 | 和 `NSScreen.frame`、`NSWindow.frame`、`NSEvent.mouseLocation` 打交道的那一小段代码 |
| 屏内坐标 | 某块屏的左上角 | 向下 | 叠加层在每块屏的窗口里定位 |

换算一律用下面的函数，**不要手写"屏高减 y"**（矩形换算要用下边缘，手写很容易错）。

### 1.3 类型

**`DisplayID`**：显示器编号，等同 `CGDirectDisplayID`。只在本次开机期间稳定。

**`DisplayInfo`**：一块显示器。

| 字段 | 含义 |
|---|---|
| `id` | 显示器编号 |
| `frame` | 这块屏在全局坐标里的矩形（点）。主屏的原点恒为 (0, 0) |
| `scale` | 1 点等于几个像素（内屏 2，普通外接屏 1） |
| `isPrimary` | 是否主屏 |
| `localPoint/Rect(fromGlobal:)`、`globalPoint/Rect(fromLocal:)` | 全局 ↔ 屏内 |
| `screen`（需主线程） | 对应的 `NSScreen` |

**`DisplayLayout`**：当前所有显示器的排列。值类型，可以随意跨线程传递。

| 成员 | 含义 |
|---|---|
| `DisplayLayout.current()` | 读取当前布局。只用 CoreGraphics，不需要授权，任何线程可调，耗时可忽略。显示器全部睡着时（息屏、锁屏后息屏）给出和醒着时相同的布局，不会变成空的 |
| `init(displays:)` | 自己造一个布局（写测试用） |
| `displays` | 所有显示器，主屏排第一 |
| `primary`、`primaryHeight` | 主屏、主屏高度 |
| `bounds` | 包住所有屏的最小矩形 |
| `display(withID:)` | 按编号找 |
| `display(containing:)` | 点在哪块屏上；不在任何屏上为 nil |
| `display(nearestTo:)` | 离点最近的屏 |
| `display(bestFor:)` | 矩形"算在哪块屏上"：相交面积最大的那块；都不相交取最近的 |
| `appKitPoint/Rect(fromGlobal:)`、`globalPoint/Rect(fromAppKit:)` | 全局 ↔ AppKit，对任何一块屏上的点都成立 |

**`CoordinateConversion`**：上面四个全局 ↔ AppKit 换算的纯函数版本（只需要主屏高度这一个参数）。

**`EdgeOutsets`**：矩形向四周外扩的距离（点）。`top` 朝屏幕上方（y 减小）。配套 `CGRect.expanded(by:)`。

几何小工具：`CGRect.center`、`CGRect.distance(to:)`（点到矩形的最短距离）、`CGPoint.distance(to:)`、
`CGPoint.offset(from:)`、`CGPoint.moved(by:)`、`CGVector.length`、`CGVector.negated`。

- **谁产生**：`DisplayLayout.current()` 谁需要谁读（叠加层建窗、图标桥判断图标在哪块屏）。
- **线程**：全部是值类型和纯函数，任何线程；只有 `DisplayInfo.screen`、`NSScreen.ddmDisplayID` 要在主线程。
- **显示器变化**：插拔、改分辨率、改排列之后布局会变，需要重新 `current()`。屏幕睡眠和唤醒本身不改变布局。

### 1.4 示例

```swift
let layout = DisplayLayout.current()          // 测试里用 DisplayLayout(displays: [...]) 造一个

// AppKit → 全局：例如把 NSEvent.mouseLocation 换成全局坐标。
let mouse = layout.globalPoint(fromAppKit: CGPoint(x: 200, y: 900))        // (200, 82)

// 全局 → AppKit：例如给 NSWindow.setFrame 用。
let windowFrame = layout.appKitRect(fromGlobal: external.frame)

// 全局 → 屏内：图标在它所在那块屏的窗口里的位置。
let display = layout.display(bestFor: iconRect)!
let local = display.localRect(fromGlobal: iconRect)
```

## 2. 桌面图标与图标提供者

代码：`Icons.swift` · 产生者：IconBridge · 消费者：应用入口（转交）、InputSense、Emotion

### 2.1 `IconID`——不可读的稳定编号

一个 64 位整数。图标桥保证：

- 同一个桌面项目在多次读取之间编号不变；**尽量**跨启动也不变（这样它每次长得一样）。
- 编号里不含文件名的任何片段，也不能反推出文件名（建议：每次安装随机生成的盐 + 名字，取哈希）。
- 改名后算作"旧的消失、新的出现"是可以接受的。

对外**绝不暴露文件名**：文件名只在图标桥内部使用，不进日志、不进任何 DDMCore 类型。

`iconID.faceSeed` 是由编号派生的**长相种子**（§4）。`"\(iconID)"` 输出形如 `icon#3fa91c02`，供调试。

### 2.2 `DesktopIcon`——一个图标

| 字段 | 类型 | 含义 |
|---|---|---|
| `id` | `IconID` | 编号 |
| `kind` | `IconKind` | 种类：`file` 文件 / `folder` 文件夹 / `application` 应用 / `volume` 磁盘 / `other` 其它 |
| `imageRect` | `CGRect` | **图标图像的矩形**（全局坐标）。画脸用：脸就画在这个矩形上 |
| `labelRect` | `CGRect?` | 文字标签的矩形（估算）。读不到为 nil |
| `displayID` | `DisplayID?` | 所在显示器。判断不出为 nil |
| `modifiedAt` | `Date?` | 最近修改时间。读不到为 nil（这样的图标不打瞌睡）。不必每次轮询都重读 |

**可点击区域 = 图像矩形 ∪ 标签矩形**。两个方法：

- `hitTest(_ point:)`：精确判断，点在图像上或标签上才算命中。**命中测试用这个。**
- `hitBounds`：上面两者的外接矩形，只适合粗筛。标签通常比图像宽，外接矩形的两个空角是点不中图标的。

### 2.3 变化事件 `IconChange`

| 事件 | 含义 |
|---|---|
| `.added(icon)` | 桌面上多了一个图标 |
| `.removed(icon, trashed:)` | 一个图标消失了。`icon` 是它消失前最后的样子（含最后位置）；`trashed` 是 `TrashVerdict`：`yes` 确认进了废纸篓 / `no` 确认没进 / `unknown` 查不出 |
| `.moved(from:, to:)` | 一个图标换了位置。`from` 旧样子、`to` 新样子，编号相同 |

- `trashed` 是图标桥通过访达查询废纸篓得到的线索。事件发出后**不会再更正**——图标桥应尽量查清了再发，查不清就给 `unknown`。
- 只是修改时间之类的变化不产生事件，直接体现在下一份快照里。

### 2.4 外观设置 `DesktopAppearance` 与状态 `IconProviderStatus`

`DesktopAppearance`：访达桌面的显示选项。`iconSize`（图标边长，点）、`textSize`（文字大小，点）、
`labelPosition`（类型 `LabelPosition`：`bottom` 标签在下 / `right` 标签在右）。还没读到时用 `.finderDefault`（64 / 12 / 下）。

`IconProviderStatus`：

| 状态 | 含义 |
|---|---|
| `starting` | 还没完成第一次读取（包括系统授权弹窗正等用户回答的期间） |
| `ok` | 正常 |
| `finderUnavailable` | 访达没运行、正在重启，或很长时间不回应（见下面"访达一时没空"）。其它归不了类的读取失败也算这里 |
| `permissionDenied` | 用户拒绝了"控制访达" |
| `stacksEnabled` | 桌面开启了叠放，位置不可靠 |

**只有 `ok` 时快照里的图标才可信；其余状态下快照的图标列表一律为空**——宁可不画，也不乱画。
判断用 `status.isUsable`。

**访达一时没空，不算不可用。** 真人实测（macOS 27.0.1）：访达一旦把图标**拖起来**，就不再回应任何询问，一直到松手；
只是按着鼠标、还没拖起来时照常回应；拖动途中访达报告的位置不变，松手后才是新位置。所以约定：

- 访达没空回答时，图标桥**保留上一份快照和状态，不上报**；访达一回答（通常就是松手的那一刻）立刻完整读一遍并上报变化。
  连续很久（图标桥定为 5 分钟）一个请求都不回答，才报 `finderUnavailable`。
- 对消费者的含义：**拖拽进行中，快照是"拖起来之前"的样子**，被拖的图标在快照里还在原位；
  松手时 `refreshNow()` 引发的回调要等访达忙完才来（实测松手后 65～95 毫秒）。
- 应用在拖拽进行中**不要**把读取节奏设为 `suspended`：从 `suspended` 恢复是整体重载（见 §2.6），
  松手后的"移动""消失"事件会因此丢掉。保持原来的节奏即可，图标桥自己扛得住。

### 2.5 快照 `IconSnapshot`

某一时刻桌面的全貌。值类型，可随意跨线程传递。

| 字段 | 含义 |
|---|---|
| `icons` | 所有桌面图标。顺序没有含义，但应尽量保持稳定 |
| `appearance` | 读取时的外观设置 |
| `status` | 读取时的状态 |
| `capturedAt` | 这次读取**开始**的时刻（单调时钟，秒，§10）。含义："快照反映的是不早于这一刻的桌面" |
| `revision` | 内容版本号：图标、外观、状态任一变了就加一；只是重读一遍而内容没变则不变 |

辅助：`icon(withID:)` 按编号找；`icon(at:)` 找出某点命中的图标；`IconSnapshot.empty()` 空快照。

### 2.6 更新 `IconUpdate`

图标桥的一次"上报"，也是应用每帧喂给交互感知和情绪引擎的图标输入。

| 字段 | 含义 |
|---|---|
| `snapshot` | 最新的快照 |
| `changes` | 相对上一份快照的变化，按发生顺序 |
| `isReset` | **整体重载**：快照被整个换掉了，而不是"某几个图标变了" |

**整体重载**发生在：第一次读到图标；状态切换（访达重启、授权变化、叠放开关）；外观设置或显示器排列变了导致所有矩形一起变；
从 `.suspended` 恢复后的第一次读取。此时 `changes` 恒为空，消费者应当**按新快照无动画地重建自己的状态**——
不要把一桌图标都当成"新来的"，也不要给"不见了"的图标放幽灵。

`a.merging(b)`：把更晚的一次上报并进来（两帧之间可能收到不止一次）。快照取最新，变化事件按顺序接起来；
其中任何一次是整体重载，结果就是整体重载。`IconUpdate.unchanged(snapshot)`：这一帧没有任何变化。

### 2.7 协议 `IconProviding`

```swift
@MainActor
public protocol IconProviding: AnyObject {
    var snapshot: IconSnapshot { get }
    var onUpdate: (@MainActor (IconUpdate) -> Void)? { get set }
    func start()
    func stop()
    func refreshNow()
    func setPollingPace(_ pace: IconPollingPace)
}
// 另有便利属性 status、appearance（取自 snapshot）。
```

| 成员 | 约定 |
|---|---|
| `snapshot` | 最近一次读到的快照。只取缓存，不触发读取。`start()` 之前是 `.empty()` |
| `onUpdate` | 有新情况时在主线程回调。触发时机见下 |
| `start()` | 发起第一次读取并按节奏持续轮询。重复调用无副作用 |
| `stop()` | 停止并取消未完成的读取，之后不再回调。可再次 `start()` |
| `refreshNow()` | **立即重读一次**（应用在鼠标松开等时刻调用）。不阻塞，结果经 `onUpdate` 送达。如果已有一次读取正在进行，要保证在它之后**再读一次**，使结果不早于这次调用 |
| `setPollingPace(_:)` | 节奏提示：`suspended` 停止读取（应用被暂停或桌面看不见）/ `idle` 用户有一阵没动了，可以读得很慢 / `active` 用户正在操作。每档具体多久读一次由图标桥自己定 |

**`onUpdate` 的触发时机：**

1. 第一次读取完成（`isReset == true`）；
2. 之后任何一次读取发现图标、外观或状态有变化；
3. `refreshNow()` 引发的读取完成时——**即使没有变化也要回调一次**（`changes` 为空、`revision` 不变、`capturedAt` 更新）。
   交互感知靠它确认"松手之后已经重读过了"，才能下"取消"的结论。

普通的定时轮询如果什么都没变，不回调（避免无谓地唤醒帧循环）。

**线程**：协议里的所有成员都在主线程调用并**立即返回**；真正的读取（向访达发请求，约 0.27 秒 / 19 个图标）
必须在后台，绝不能阻塞主线程；`onUpdate` 在主线程回调。详见 §8。

**授权**：应用只需要"控制访达"一项授权。图标桥只向访达询问，不直接读取桌面文件夹。

### 2.8 示例

```swift
// 消费方：处理一次上报。
if update.isReset {
    // 整体重载：按 update.snapshot 无动画地重建
}
for change in update.changes {
    switch change {
    case let .added(icon):
        log.append("新增 \(icon.kind.rawValue)")
    case let .removed(icon, trashed):
        log.append("消失 \(icon.kind.rawValue)，进废纸篓：\(trashed.rawValue)")
    case let .moved(from, to):
        log.append("移动 \(to.imageRect.minX - from.imageRect.minX),\(to.imageRect.minY - from.imageRect.minY)")
    }
}

// 命中测试：鼠标点在哪个图标上。
let hit = update.snapshot.icon(at: mousePosition)
```

```swift
/// 实现方的骨架——慢的读取放后台，读完回主线程上报。
@MainActor
final class SketchIconProvider: IconProviding {
    private(set) var snapshot: IconSnapshot = .empty()
    var onUpdate: (@MainActor (IconUpdate) -> Void)?
    private var isRunning = false

    func start() {
        guard !isRunning else { return }
        isRunning = true
        read(isReset: true)
    }

    func stop() { isRunning = false }
    func refreshNow() { read(isReset: false) }
    func setPollingPace(_ pace: IconPollingPace) {}

    private func read(isReset: Bool) {
        let startedAt = ProcessInfo.processInfo.systemUptime   // capturedAt 取读取"开始"的时刻
        Task.detached(priority: .utility) { [weak self] in
            let icons = SketchIconProvider.readFromFinder()                           // 慢：在后台线程
            await self?.publish(icons, capturedAt: startedAt, isReset: isReset)       // 回主线程上报
        }
    }

    /// 必须标 nonisolated：否则它跟着类一起被隔离在主线程，"后台读取"就成了在主线程读。
    /// 真正的实现在这里向访达发请求；示例里直接返回一个假图标。
    private nonisolated static func readFromFinder() -> [DesktopIcon] {
        [DesktopIcon(id: IconID(rawValue: 1), kind: .folder, imageRect: CGRect(x: 100, y: 100, width: 64, height: 64))]
    }

    private func publish(_ icons: [DesktopIcon], capturedAt: TimeInterval, isReset: Bool) {
        guard isRunning else { return }
        let changed = icons != snapshot.icons || snapshot.status != .ok
        snapshot = IconSnapshot(
            icons: icons, status: .ok, capturedAt: capturedAt,
            revision: snapshot.revision + (changed ? 1 : 0)   // 内容变了才加一
        )
        onUpdate?(IconUpdate(snapshot: snapshot, isReset: isReset))
    }
}
```

这个骨架省略了轮询、比对变化事件、状态处理，只为说明线程怎么走。

## 3. 交互事实与交互感知

代码：`Interaction.swift` · 产生者：InputSense · 消费者：Emotion、应用入口

交互感知只陈述**事实和数值**（"鼠标离废纸篓 80 点、正朝它去"），不谈情绪。事实分两类：

- **状态**：每帧都有当前值——鼠标、悬停、拖拽、等待结局的拖拽、废纸篓。
- **一次性事件**：只在产生的那一帧出现一次，下一帧就没有了——拖拽结局、删除。

### 3.1 状态

**`MouseState`**

| 字段 | 单位 | 含义 |
|---|---|---|
| `position` | 全局坐标，点 | 鼠标位置 |
| `buttons` | `MouseButtons` | 按下的按键集合：`.left` `.right` `.other` |
| `velocity` | 点/秒 | 速度（已平滑）。`speed` 是它的大小 |
| `idleDuration` | 秒 | 鼠标已经静止了多久，一动就归零（"无聊"彩蛋用） |

**`HoverState`**：鼠标正停在某个图标上——已确认该处桌面没被别的窗口挡住、且没有按键按下。
`iconID` 哪个图标；`duration` 已悬停多久（秒）。

**`DragState`**：一次正在进行的拖拽（左键按住、已移动超过起拖阈值）。松手后它就消失，转为 `ReleasedDrag`。

| 字段 | 单位 | 含义 |
|---|---|---|
| `iconID` | | 被抓住的图标。多选拖拽只认鼠标抓住的那一个 |
| `grabOffset` | 点 | **抓取偏移 = 按下瞬间的鼠标位置 − 图标图像矩形的左上角** |
| `originImageRect` | 全局坐标 | 被抓起时图标图像矩形（原位置） |
| `position` | 全局坐标 | 当前鼠标位置 |
| `velocity` | 点/秒 | 当前速度 |
| `shake` | 0…1 | 甩动强度：来回急甩越猛越高，平稳拖动接近 0 |
| `startedAt` | 单调时钟，秒 | 拖拽开始（越过起拖阈值）的时刻 |
| `currentImageRect` | 全局坐标 | **拖影上图标图像的矩形 = 鼠标位置 − 抓取偏移**，大小不变 |

> 拖拽期间图标桥报告的图标位置**不会变**，松手后才更新。所以被拖图标的脸要画在 `currentImageRect`，不是快照里的 `imageRect`。

**`ReleasedDrag`**：已经松手、结局还没判出来的拖拽（在等图标桥的新快照）。
`iconID`、`releasePoint` 松手时的鼠标位置、`imageRectAtRelease` 松手那一刻拖影的图像矩形、`releasedAt` 松手时刻。
结局一出，它从列表里消失，同一帧出现对应的 `DragOutcome`。

**`TrashInfo`**：废纸篓在哪、鼠标和它的关系。位置是估算的（按程序坞设置推算 + 自学习修正）。

| 字段 | 单位 | 含义 |
|---|---|---|
| `estimatedRect` | 全局坐标 | 估算出的废纸篓区域 |
| `confidence` | 0…1 | 可信度：纯推算时较低，被实际删除"教"过之后升高 |
| `distance` | 点 | 鼠标到估算区域的距离；在区域内为 0 |
| `closingSpeed` | 点/秒 | 鼠标朝废纸篓靠近的速度；正 = 靠近，负 = 远离 |
| `isApproaching` | | 是否正朝它移动（已防抖，比直接看 `closingSpeed` 的正负稳） |
| `isOver` | | 鼠标是否已在废纸篓上方 |

### 3.2 一次性事件

**`DragOutcome`**：一次拖拽的结局。`iconID`、`kind`（类型 `DragOutcomeKind`）、`releasePoint` 松手时的鼠标位置、`newImageRect` 图标的新图像矩形（仅 `.moved` 时有）。

| `kind` | 含义 |
|---|---|
| `moved` | 在桌面上挪了位置 |
| `trashed` | 进了废纸篓 |
| `leftDesktop` | 离开桌面去了别处（文件夹、窗口、别的应用），但没进废纸篓 |
| `cancelled` | 取消：弹回原位，什么都没变 |
| `unknown` | 等了规定时间仍判断不出 |

结局不是松手的那一帧就有的（真人实测与交互感知的做法）：`moved`、`trashed` 最快约 0.1 秒确认；
`cancelled` 是故意多等一会儿才下的结论——松在桌面上约 0.4 秒，松在窗口或程序坞上约 1.1 秒——免得把访达慢半拍的搬动当成取消；
最多等 3 秒，再判断不出就是 `unknown`。这期间 `releasedDrags` 不为空，被拖图标在快照里还在原位。

**`DeletionEvent`**：某个图标被删掉了。**情绪模块见到它就在原地放幽灵，不需要再做任何判断。**

| 字段 | 含义 |
|---|---|
| `iconID` | 哪个图标 |
| `lastImageRect` | 图标被删前在**桌面上的原位置**的图像矩形（它最后一次出现在快照里的 `imageRect`），幽灵从这里飘起。经过拖拽的删除也是原位置，**不是**松手处的拖影位置——松手处在程序坞上，画在桌面层的幽灵会被挡住 |
| `wasDragged` | 是否经过拖拽 |
| `trashed` | 图标桥给的原始线索，仅供调试和记录 |

发不发由交互感知判定：

| 图标从桌面消失，且图标桥说 | 交互感知 |
|---|---|
| `trashed == .yes`（确认进了废纸篓） | 必发 |
| `.no`（挪进了文件夹、被改名等） | 不发 |
| `.unknown`（查不出） | 按自己掌握的事实决定（例如松手点是否在废纸篓上方）；拿不准就不发——宁可少一个幽灵，也不要给没被删的文件"送葬" |

> 经过拖拽的删除，**同一帧**里既有一条 `kind == .trashed` 的 `DragOutcome`，也有一条 `DeletionEvent`。
> 没有拖拽过程的删除（快捷键、右键菜单）只有 `DeletionEvent`。

### 3.3 `InteractionFacts`——一帧的全部事实

| 字段 | 含义 |
|---|---|
| `time` | 这些事实对应的时间（就是传给 `update` 的那个） |
| `mouse` | 鼠标状态 |
| `isMouseOverDesktop` | 鼠标所在位置最上面的窗口是不是访达的桌面图标层（已排除本应用自己的叠加窗口）。为 false 时不会有悬停，也不会开始拖拽 |
| `hover` | 当前悬停；没有为 nil。拖拽期间恒为 nil |
| `drag` | 当前拖拽；没有为 nil |
| `releasedDrags` | 已松手、结局未定的拖拽 |
| `trash` | 废纸篓；完全估算不出来为 nil |
| `dragOutcomes` | 一次性：这一帧判出的拖拽结局 |
| `deletions` | 一次性：这一帧判出的删除 |
| `wantsIconRefresh` | 给应用的信号：请立即调用图标桥的 `refreshNow()`（例如刚松手，需要尽快知道图标去哪了）。可以连续多帧为 true，应用每次都会照办 |
| `demand` | 省电信号（§10）：鼠标在动时 `.continuous`；静止时给一个较远的时刻，降低读鼠标的频率 |

### 3.4 协议 `InteractionSensing`

```swift
@MainActor
public protocol InteractionSensing: AnyObject {
    func update(time: FrameTime, icons: IconUpdate) -> InteractionFacts
    func reset()
}
```

- **不自带定时器**：应用每帧调一次 `update`，它在里面读鼠标等系统状态并更新判断。暂停或桌面不可见时没有帧，它自然就停了。
- 图标快照和变化事件由应用从图标桥**转交**，本模块不依赖图标桥。
- `reset()`：丢弃进行到一半的判断（悬停计时、拖拽、等待中的结局）。应用在"暂停后恢复""桌面重新可见"时调用。学到的废纸篓位置不受影响。
- **排除自家窗口**：判断"鼠标处最上面的窗口是不是桌面图标层"时，要排除本应用自己的叠加窗口（桌面层和拖拽层）——按窗口所属进程是不是本进程来排除即可，不需要叠加层提供窗口编号。
- **线程与性能**：主线程调用。`update` 在每帧的关键路径上，目标 0.5 毫秒以内；较慢的系统查询（如窗口列表）要自己限频或挪到后台。

### 3.5 示例

```swift
let facts = sensor.update(time: time, icons: update)

// 被拖图标的脸画在拖影上：鼠标位置 − 抓取偏移。
if let drag = facts.drag {
    let faceRect = drag.currentImageRect
}
// 离废纸篓多近、是不是正朝它去、是不是已经在它上方。
if let trash = facts.trash, trash.isOver { /* … */ }

// 一次性事件：松手后的某一帧里出现一次。
for outcome in facts.dragOutcomes {
    switch outcome.kind {
    case .trashed: break                               // 真的被删了
    case .moved, .leftDesktop, .cancelled: break       // 虚惊一场
    case .unknown: break                               // 判断不出来
    }
}
for deletion in facts.deletions {
    let ghostStartsAt = deletion.lastImageRect         // 幽灵从这里飘起
}
```

## 4. 表情状态

代码：`Faces.swift` · 产生者：Emotion · 消费者：Faces（经应用入口转交）

### 4.1 分工

| 归情绪模块（Emotion） | 归表情模块（Faces） |
|---|---|
| 是什么情绪、多强 | 这些参数**长什么样** |
| 什么时候眨眼（随时间驱动 `blink`） | 眼皮闭到一半是什么形状 |
| 看向哪里（`gazeTarget`、`gazeFollow`） | 瞳孔怎么转、离得近时怎么对眼 |
| 参数随时间的渐入渐出 | **循环小动画**怎么动：泪珠下落、Zzz 飘动、发抖、星星转圈 |
| 每个图标的性格（由长相种子决定） | 每个图标五官的细微差别（由长相种子决定） |

一句话：`FaceState` 里的每个数都由情绪模块给出；表情模块只管"给定这些数和一个时间，画面是什么"。

### 4.2 `FaceMood`——八种情绪，不再新增

`calm` 平静 · `shy` 害羞 · `dizzy` 头晕 · `scared` 害怕 · `crying` 哭 · `coveringEyes` 捂眼 · `dozing` 打瞌睡 · `ghost` 幽灵

### 4.3 `FaceState`

`mood` 是**主导情绪的标签**；真正的"多强"由连续参数给出。表情之间靠连续参数平滑过渡——害怕 0.3、困意 0.6 这样的中间状态也要成立。
所以表情模块应当**主要依据连续参数作画**，让 `mood` 切换的那一帧画面不跳变；`mood` 只用于无法连续化的造型选择和调试输出。
唯一允许突变的是幽灵的出现。

所有强度参数范围都是 **0…1**，0 表示"没有"，默认全为 0。也就是说 `FaceState(seed:)` 就是一张平视前方、睁着眼的平静的脸。

| 字段 | 范围 | 含义 |
|---|---|---|
| `mood` | 八选一 | 主导情绪 |
| `seed` | `UInt64` | **长相种子**：让每个图标的五官略有不同，同一个图标永远相同。取自 `IconID.faceSeed` |
| `gazeTarget` | 点，`CGVector` | 视线目标相对**图标图像矩形中心**的位移，y 向下。鼠标在图标右下方 100 点处就是 (100, 100) |
| `gazeFollow` | 0…1 | 视线跟随程度：0 = 平视前方（看着屏幕外的用户），1 = 完全看向 `gazeTarget` |
| `blink` | 0…1 | 闭眼程度：0 睁开，1 完全闭上 |
| `blush` | 0…1 | 脸红 |
| `fear` | 0…1 | 惊恐：瞳孔缩小、眼睛瞪大 |
| `sweat` | 0…1 | 汗 |
| `tremble` | 0…1 | 发抖幅度 |
| `tears` | 0…1 | 泪：小值泪汪汪，接近 1 眼泪直流 |
| `dizziness` | 0…1 | 头晕：眼睛转圈、冒星星 |
| `cover` | 0…1 | 捂眼：手抬起、遮住眼睛的程度 |
| `peek` | 0…1 | 偷看：捂着眼时指缝张开多大。只在 `cover > 0` 时有意义 |
| `sleepiness` | 0…1 | 困意：0 清醒，1 睡熟 |
| `ghost` | 0…1 | 幽灵进度：0 刚冒出来，1 完全消散。只在 `mood == .ghost` 时有意义。**约定**：幽灵随进度匀速上升，进度为 p 时它的中心比图标图像矩形的中心高 p × 一个图标高度（到消散时正好升了一个图标高）。情绪模块据此算"目送幽灵"的视线目标，表情模块据此作画 |

为什么 `gazeTarget` 用相对位移而不是全局坐标：这样表情状态与图标在屏幕上的位置无关——同样的 `FaceState`、同样大小的图标，永远画出同样的画面，
方便出样张、做测试，也让叠加层可以"只移动不重画"。换算只要一行：`target.offset(from: rect.center)`。

辅助：

- `FaceState.unitParameters`：全部 12 个 0…1 参数的（名字, 键路径）清单，写测试、打印时间线时遍历用。
- `state.isValid`：所有 0…1 参数都在范围内且视线目标是有限数。
- `state.clamped()`：把越界的值夹回范围（非数字按 0）。应用在把表情交给表情模块前会做这一步，所以表情模块收到的总是合法值。

### 4.4 示例

```swift
var state = FaceState(seed: icon.id.faceSeed)   // 默认：平静、平视前方、睁着眼
state.mood = .scared
state.gazeTarget = trashCenter.offset(from: icon.imageRect.center)   // 死盯废纸篓
state.gazeFollow = 1
state.fear = 0.7
state.sweat = 0.5
state.tremble = 0.3
```

## 5. 情绪引擎

代码：`Emotion.swift` · 实现者：Emotion · 调用者：应用入口

情绪引擎是"导演"：每帧拿到图标、交互事实和时间，决定这一帧要画哪些脸、各自在哪、是什么表情。

### 5.1 类型

**`OverlayLayer`**：`desktop` 桌面层（平时所有的脸都在这层）/ `drag` 拖拽层（画正被拖着的那个图标的脸；
松手之后、结局出来之前停在松手处的那一小会儿，以及飘回原位的途中，这张脸也仍在拖拽层）。详见 §7。

**`FacePlacement`**：一张要画的脸。

| 字段 | 含义 |
|---|---|
| `iconID` | 这张脸属于哪个图标。幽灵沿用被删图标的编号 |
| `rect` | 图标图像矩形（全局坐标），脸画在这上面。被拖着的图标用 `DragState.currentImageRect`；幽灵用图标被删前最后的矩形 |
| `layer` | 画在哪一层 |
| `state` | 表情 |

约定：**同一帧里，同一个（图标，层）组合最多出现一次。**

**`EmotionInput`**：`time` 这一帧的时间；`icons` 图标快照与变化事件（和喂给交互感知的是同一份 `IconUpdate`）；`facts` 交互感知这一帧给出的事实。

**`EmotionOutput`**：`faces` 这一帧要画的全部的脸（不在清单里的图标这一帧不画；数组顺序就是同一层内的叠放次序，排在后面的画在上面，例如幽灵放最后）；`demand` 省电信号（§10）：
`.continuous` = 有参数还在逐帧变化；`.by(t)` = 现在是静止的，但最晚 t 时刻要再算一次（如下一次眨眼）；`.idle` = 除非有新输入，否则不必再算。
只需考虑情绪参数自身的变化——表情模块的循环小动画由应用另行处理（§6 的 `animationInterval`）。

### 5.2 协议 `EmotionDirecting`

```swift
public protocol EmotionDirecting {
    mutating func update(_ input: EmotionInput) -> EmotionOutput
    mutating func reset()
}
```

- **纯逻辑**：不读系统时钟、不用全局随机数、不做文件读写、不依赖 AppKit。时间由 `input.time` 传入，随机数种子在构造时传入（`EmotionDirector(seed:)`，随机数用 `SeededRandom`，§10）。
- **确定性**：同样的种子 + 同样的输入序列 → 永远同样的输出序列。
- `input.time.monotonic` 保证单调不减。打瞌睡要比较"现在"和图标的修改时间，用 `input.time.wallClock`。
- `icons.isReset` 为 true 时按新快照无动画地重建，不要当成一桌新图标（§2.6）。
- `reset()`：清空所有进行中的情绪和动画，回到初始状态（随机数序列也从种子重新开始）。应用在"暂停后恢复""桌面重新可见"时调用。
- **线程**：不绑定线程；应用里在主线程逐帧调用。
- **性能目标**：100 个图标一次 `update` 不超过约 0.2 毫秒。

### 5.3 示例

```swift
/// 一个最小的情绪引擎——鼠标悬停的图标脸红，其余平静，所有人都看着鼠标。
struct BlushOnHoverDirector: EmotionDirecting {
    mutating func update(_ input: EmotionInput) -> EmotionOutput {
        let mouse = input.facts.mouse.position
        let faces = input.icons.snapshot.icons.map { icon -> FacePlacement in
            var state = FaceState(seed: icon.id.faceSeed)
            state.gazeTarget = mouse.offset(from: icon.imageRect.center)   // 视线目标：相对图标中心
            state.gazeFollow = 1
            if input.facts.hover?.iconID == icon.id {
                state.mood = .shy
                state.blush = 1
            }
            return FacePlacement(iconID: icon.id, rect: icon.imageRect, layer: .desktop, state: state)
        }
        return EmotionOutput(faces: faces, demand: .idle)
    }

    mutating func reset() {}
}
```

```swift
// 调用方：逐帧推进。
var director = EmotionDirector(seed: 42)
let output = director.update(EmotionInput(time: time, icons: update, facts: facts))
for face in output.faces { /* 交给叠加层和表情绘制者 */ }
```

## 6. 表情绘制者

代码：`Faces.swift` · 实现者：Faces · 调用者：应用入口（在叠加层的绘制回调里）

### 6.1 协议 `FaceRendering`

```swift
public protocol FaceRendering: Sendable {
    func draw(_ state: FaceState, in iconRect: CGRect, context: CGContext, time: TimeInterval)
    func outsets(for state: FaceState, iconSize: CGSize) -> EdgeOutsets
    func animationInterval(for state: FaceState) -> TimeInterval?
}
```

**`draw`**——画一张脸。

| 参数 | 含义 |
|---|---|
| `state` | 表情状态。收到的总是合法值（已夹到范围内） |
| `iconRect` | 图标图像矩形，位于 `context` 当前的坐标系里。给的是哪里就画在哪里 |
| `context` | 画布。坐标系：**y 向下、单位点**；缩放已由叠加层设好，直接按点作画，内屏 2x、外接屏 1x 都会清晰。画布已清空为全透明 |
| `time` | 这一帧的单调时间（秒）。循环小动画的相位由它决定 |

- **无状态**：同样的（表情状态、图标矩形大小、时间）永远画出同样的画面。
- **不依赖绝对位置**：画面不得依赖 `iconRect` 在屏幕上的位置——叠加层可能只移动画布而不重画。
- **不越界**：绘制范围不得超出 `iconRect.expanded(by: outsets(for: state, iconSize: iconRect.size))`；超出的部分会被裁掉。

**`outsets`**——这个表情状态最多会画到图标图像矩形外面多远（点）。眼泪往下、汗滴往旁边、Zzz 和幽灵往上。
应用把它交给叠加层，用来决定每张脸的画布留多大。
返回值应当**成档稳定**：只随"哪些效果出现了"变化，不要随强度连续变化——否则叠加层每帧都得改画布大小。

**`animationInterval`**——这个表情状态的画面多久需要重画一次（循环小动画的刷新间隔，秒）。

| 返回值 | 含义 | 应用怎么做 |
|---|---|---|
| `nil` | 画面不随 `time` 变化，没有循环小动画 | 只要表情状态不变，这张脸就不重画 |
| `0` | 每个显示刷新都要重画（泪珠下落、发抖、星星转圈这类快动画） | 这张脸每帧重画，并保持连续出帧 |
| 正数 | 至少每隔这么久重画一次（Zzz 飘动、缓慢起伏这类慢动画，例如 `0.1`） | 到点才重画一次，其余时间可以休息 |

**这是省电的关键。** 没有动画务必返回 `nil`；慢动画给一个够用的间隔，不要一律返回 `0`——
桌面上有图标在打瞌睡是常态，不能因此让整个应用一直满帧重画。

- **线程**：不绑定线程，任何线程都可以调用（出样张时可以在后台画）；应用里是在主线程。
- **性能目标**：64 点图标、2x 下，单张脸一次绘制平均不超过约 0.3 毫秒。

### 6.2 示例

```swift
/// 一个最小的表情绘制者——在图标中央画两个黑点当眼睛，哭的时候画布向下多留半个图标。
struct DotEyesRenderer: FaceRendering {
    func draw(_ state: FaceState, in iconRect: CGRect, context: CGContext, time: TimeInterval) {
        // 画布是 y 向下、单位点；iconRect 给的是哪里，就画在哪里。
        let radius = iconRect.width / 16
        context.setFillColor(gray: 0, alpha: 1)
        for side in [-1.0, 1.0] {
            let center = CGPoint(x: iconRect.midX + side * iconRect.width / 6, y: iconRect.midY)
            context.fillEllipse(in: CGRect(x: center.x - radius, y: center.y - radius, width: radius * 2, height: radius * 2))
        }
    }

    func outsets(for state: FaceState, iconSize: CGSize) -> EdgeOutsets {
        // 成档变化：有泪就向下多留半个图标高，没有就不外扩。
        state.tears > 0 ? EdgeOutsets(bottom: iconSize.height / 2) : .zero
    }

    func animationInterval(for state: FaceState) -> TimeInterval? {
        if state.tears > 0 { return 0 }           // 泪珠下落：每帧都要重画
        if state.sleepiness > 0 { return 0.1 }    // 缓慢起伏：每秒 10 次就够
        return nil                                // 其余是静止画面：表情不变就不重画
    }
}
```

## 7. 叠加层宿主

代码：`Overlay.swift` · 实现者：Overlay · 调用者：应用入口

叠加层只管"画布"：在屏幕的正确位置、正确层级，以流畅且省电的方式把别人给的内容显示出来。
它不知道画的是脸——它只认识一个个**画布项**：一个矩形、一个版本号，需要重画时回调调用方。

### 7.1 两层画布

| 层 | 窗口 | 用途 |
|---|---|---|
| `OverlayLayer.desktop` 桌面层 | 每块显示器一个透明、点击穿透的窗口，层级为"桌面图标层 +1"：压在访达图标之上、普通窗口之下 | 平时所有的脸。图标被普通窗口挡住时，脸也自然被挡住 |
| `OverlayLayer.drag` 拖拽层 | 一个透明、点击穿透的最上层窗口（高于普通窗口和程序坞）。**只要这一帧的清单里有 `.drag` 项就显示，没有就隐藏** | 只画"正被拖着的那个图标"的脸，让它跟着鼠标走到废纸篓上方时仍然看得见 |

### 7.2 `OverlayItem`——一小块画布

| 字段 | 含义 |
|---|---|
| `iconID`、`layer` | 合起来是这块画布的身份（`key`）。同一个 key 跨帧视为同一块画布 |
| `rect` | 基准矩形（图标图像矩形），全局坐标 |
| `outsets` | 画布比基准矩形向四周各多出多少 |
| `contentVersion` | 内容版本号 |
| `canvasRect` | 画布矩形 = `rect` 外扩 `outsets`，全局坐标。绘制被裁剪在这个范围内 |

**"没变化就不重画"的规则**（按 key 比较新旧两帧）：

| 情况 | 叠加层怎么做 |
|---|---|
| `contentVersion`、画布尺寸都没变，位置也没变 | 什么都不用做 |
| 只有位置变了 | 可以只移动画布，不必重画 |
| `contentVersion` 变了，或画布尺寸（`rect.size` / `outsets`）变了 | **必须**回调 `drawOverlayItem` 重画 |
| 上一帧有、这一帧没有 | 移除 |
| 这一帧新出现 | 新建并回调重画 |

表里是"至少要做到的事"。叠加层内部用整窗重画还是每张脸一个小图层，由它实测后自己定；多画几次不算违约，该重画时没重画才算。

矩形跨两块屏时也要画对——叠加层可以对同一项在每块屏上各回调一次。

### 7.3 帧回调 `OverlayFrameSource`（由应用入口实现）

```swift
@MainActor
public protocol OverlayFrameSource: AnyObject {
    func overlayFrame(at time: FrameTime) -> OverlayFrame
    func drawOverlayItem(_ item: OverlayItem, in context: CGContext, at time: FrameTime)
}
```

**`overlayFrame(at:)`**：取这一帧的内容。调用方在这里推进自己的全部逻辑（§0.2）。
每帧恰好调用一次；应用被暂停、桌面不可见时不调用。返回 `OverlayFrame`：

- `items`：这一帧的全部画布项。同一个 key 最多出现一次。数组顺序就是同一层内的叠放次序：排在后面的画在上面。
- `demand`：下一帧什么时候要（§10）。

**`drawOverlayItem(_:in:at:)`**：画一个画布项。只在叠加层判定该项需要重画时调用，
调用时机在本帧 `overlayFrame(at:)` 返回之后、下一次 `overlayFrame(at:)` 之前。

- `context` 已由叠加层准备好：坐标系就是**全局坐标**（y 向下、单位点），所以直接用 `item.rect` 作画，不必做任何换算；
  已裁剪到 `item.canvasRect`；已清空为全透明；缩放已设好。
- `time` 与本帧 `overlayFrame(at:)` 的相同。
- 同一项在同一帧里可能被调用不止一次（跨屏时每块屏各一次），所以绘制必须是幂等的。

### 7.4 协议 `OverlayHosting`

```swift
@MainActor
public protocol OverlayHosting: AnyObject {
    var frameSource: (any OverlayFrameSource)? { get set }
    var isDesktopVisible: Bool { get }
    var onDesktopVisibilityChange: (@MainActor (Bool) -> Void)? { get set }
    func start()
    func stop()
    func requestFrame()
}
```

| 成员 | 约定 |
|---|---|
| `frameSource` | 帧回调的接收方。实现应**弱引用**它 |
| `isDesktopVisible` | 桌面层此刻是否对用户可见。以下情况为 false：在全屏应用的空间、锁屏、屏幕睡眠、访达隐藏了桌面图标、所有桌面层窗口都被别的窗口完全挡住。与"暂停"无关。**只要叠加层因为"看不见"而停了帧回调，这个值就必须是 false**——应用靠它让图标桥停止读取，否则访达会在没人看的时候照旧被轮询 |
| `onDesktopVisibilityChange` | 上面这个值变化时回调（主线程）。应用用它让图标桥停止或恢复读取，并重置交互感知和情绪引擎 |
| `start()` | 建窗并开始帧循环。重复调用无副作用 |
| `stop()` | 关闭所有窗口、停止帧循环。可再次 `start()` |
| `requestFrame()` | 请求尽快出一帧（下一个显示刷新）。用于被外部事件唤醒：图标有更新、暂停被解除等。正在连续出帧时调用无影响；暂停或桌面不可见时被忽略 |

叠加层**自己负责**的事（不需要应用告诉它）：

- **帧循环**：按 `OverlayFrame.demand` 决定——`.continuous` 每个显示刷新出一帧；`.by(t)` 在 t 时刻醒一次（t 已经过了就立刻）；`.idle` 休息，直到 `requestFrame()`。
- **暂停**：自己读 `PauseSwitch.shared`（§9）。暂停时隐藏所有窗口、停止帧回调；恢复时重新显示并出一帧。
- **系统状态**：切换空间、全屏、图标被隐藏、锁屏、屏幕睡眠、显示器插拔或排列变化——自己跟随；桌面不可见时停止帧回调。
- **时间**：每帧的 `FrameTime` 由它生成（`FrameTime.now()` 或显示刷新的时间戳，同一时基）。**帧时间不得超前**：`monotonic` 不能晚于帧回调发生那一刻的 `ProcessInfo.systemUptime`——用显示刷新的时间戳时，要用"已经到了的"那个，不要用"下一次刷新的目标时刻"（原因见 §10.1）。

**安全线**：所有窗口从创建那一刻起就必须点击穿透，绝不接收鼠标和键盘事件，绝不抢焦点。

**线程**：所有成员都在主线程使用，所有回调也在主线程。

### 7.5 示例

```swift
/// 调用方：帧回调的接收方——每帧给出一个画布项，被要求重画时把它涂黑。
@MainActor
final class OneBoxSource: OverlayFrameSource {
    func overlayFrame(at time: FrameTime) -> OverlayFrame {
        let item = OverlayItem(
            iconID: IconID(rawValue: 1),
            layer: .desktop,
            rect: CGRect(x: 100, y: 100, width: 64, height: 64),
            outsets: EdgeOutsets(all: 8),
            contentVersion: 1   // 内容不变就一直用同一个版本号
        )
        return OverlayFrame(items: [item], demand: .by(time.monotonic + 1))   // 一秒后再来
    }

    func drawOverlayItem(_ item: OverlayItem, in context: CGContext, at time: FrameTime) {
        // 画布已经是全局坐标，直接用 item.rect。
        context.setFillColor(gray: 0, alpha: 1)
        context.fill(item.rect)
    }
}

let host = OverlayHost()
host.frameSource = source
host.start()
```

```swift
/// 实现方：把一块位图画布调成"全局坐标、y 向下、单位点"，并裁剪到画布矩形。
/// canvasRect 是这块画布对应的全局矩形（item.canvasRect），scale 是所在显示器的缩放。
func makeCanvas(for canvasRect: CGRect, scale: CGFloat) -> CGContext {
    let context = CGContext(
        data: nil,
        width: Int((canvasRect.width * scale).rounded(.up)),
        height: Int((canvasRect.height * scale).rounded(.up)),
        bitsPerComponent: 8, bytesPerRow: 0,
        space: CGColorSpaceCreateDeviceRGB(),
        bitmapInfo: CGImageAlphaInfo.premultipliedLast.rawValue
    )!
    // 位图画布默认原点在左下角、y 向上、单位像素。三步变成全局坐标：
    context.translateBy(x: 0, y: CGFloat(context.height))             // 1. 原点挪到左上角
    context.scaleBy(x: scale, y: -scale)                              // 2. y 翻转成向下，单位变成点
    context.translateBy(x: -canvasRect.minX, y: -canvasRect.minY)     // 3. 原点挪到全局原点
    context.clip(to: canvasRect)
    return context
}
```

用图层（CALayer）或视图作画时变换的写法不同，但交给调用方的画布必须满足同样的三点：全局坐标、y 向下、单位点。

## 8. 线程约定

一条总原则：**模块之间的一切往来都发生在主线程；慢的事情由模块自己在内部挪到后台。**

工程用 Swift 6 语言模式编译，下面的约定大部分由编译器把关（标了 `@MainActor` 的协议在别的线程调用会编译不过；
跨线程传递的类型必须是 `Sendable`——DDMCore 里所有数据类型都是）。

| 调用 | 线程 | 备注 |
|---|---|---|
| `IconProviding` 的全部成员、`onUpdate` 回调 | 主线程 | 调用必须立即返回 |
| 图标桥内部向访达发请求、解析结果 | **后台** | 约 0.27 秒 / 19 个图标，**绝不能在主线程做**；读完回主线程比对、上报 |
| `InteractionSensing.update` / `reset` | 主线程 | 每帧关键路径，目标 ≤ 0.5 毫秒；慢查询自己限频或挪后台 |
| `EmotionDirecting.update` / `reset` | 不绑定；应用里在主线程 | 纯逻辑，目标 ≤ 0.2 毫秒 / 100 个图标 |
| `FaceRendering` 的全部方法 | 不绑定；应用里在主线程 | 无状态，目标 ≤ 0.3 毫秒 / 张 |
| `OverlayHosting` 的全部成员及其回调、`OverlayFrameSource` 的全部方法 | 主线程 | |
| `PauseSwitch.isPaused`（读） | 任何线程 | |
| `PauseSwitch.setPaused` / `toggle` / `addObserver`，观察回调 | 主线程 | 只有应用外壳写 |
| `DisplayLayout.current()`、全部坐标换算、全部数据类型 | 任何线程 | 值类型，随意传递 |
| `DisplayInfo.screen`、`NSScreen.ddmDisplayID` | 主线程 | 碰 `NSScreen` |

**一帧的时间预算**：60 帧/秒时每帧约 16 毫秒。`overlayFrame(at:)` 里交互感知 + 情绪引擎 + 应用自己的开销应远小于 1 毫秒；
重画 30 张脸约 30 × 0.3 = 9 毫秒是上限情形，平时只有少数几张脸在变。

**不要阻塞主线程**：不在主线程上同步等待后台结果（信号量、`DispatchQueue.sync`、同步的 Apple 事件）；后台做完用 `await MainActor.run { … }` 或 `Task { @MainActor in … }` 回来。

## 9. 全局暂停开关

代码：`PauseSwitch.swift` · 写：应用外壳（菜单栏的「暂停 / 继续」）· 读：所有模块

```swift
PauseSwitch.shared.isPaused            // 读：任何线程，随时
PauseSwitch.shared.addObserver { paused in … }   // 观察：主线程登记，回调在主线程
PauseSwitch.shared.setPaused(true)     // 写：只有应用外壳，主线程
```

- `isPaused`：任何线程可读，极快。
- `setPaused(_:)` / `toggle()`：主线程。值没变时什么都不做；变了就**同步**通知所有观察者（按登记顺序）。
- `addObserver(_:)`：返回一个凭据（`PauseObservation`），调它的 `cancel()` 结束观察；不需要取消的话可以不保存凭据。
- 应用里各模块统一用 `PauseSwitch.shared`；测试里自己 `PauseSwitch()` 一个互不影响的。建议模块的构造函数接受 `pause: PauseSwitch = .shared` 参数，方便测试。

**暂停期间各模块该做什么：**

| 模块 | 暂停时 | 怎么知道 |
|---|---|---|
| Overlay | 隐藏所有窗口，停止帧回调；恢复时重新显示并出一帧 | 自己观察 `PauseSwitch.shared` |
| IconBridge | 停止向访达读取 | 应用会调 `setPollingPace(.suspended)`；后台线程里也可以随时读 `isPaused` 自查 |
| InputSense | 什么都不用做——没有帧就没有 `update` 调用。恢复时应用会调 `reset()` | — |
| Emotion | 同上。恢复时应用会调 `reset()` | — |
| Faces | 无状态，无需处理 | — |

### 示例

```swift
let pause = PauseSwitch()   // 应用里各模块用 PauseSwitch.shared

var log: [String] = []
let observation = pause.addObserver { paused in
    log.append(paused ? "停下" : "继续")
}
pause.setPaused(true)    // 只有应用外壳（菜单）会写
pause.setPaused(false)
observation.cancel()
// log == ["停下", "继续"]
```

## 10. 时间、省电信号、随机数

代码：`Time.swift`、`SeededRandom.swift`

### 10.1 `FrameTime`——一帧的时间

逻辑模块**不自己读时钟**：时间由叠加层在每次帧回调时生成，一路传给交互感知、情绪引擎和表情绘制。这样才能做确定性的测试。

| 字段 | 含义 |
|---|---|
| `monotonic` | **单调时钟**，秒。只增不减、不受改系统时间影响、电脑睡眠期间不走。与 `CACurrentMediaTime()`、`ProcessInfo.systemUptime` 同一时基。动画、速度、时长、截止时刻一律用它 |
| `wallClock` | **墙上时间**（`Date`）。只用来和图标的 `modifiedAt` 比较（打瞌睡），不要拿它算动画 |

**帧时间不得超前**：`monotonic` 不能晚于帧回调发生那一刻的系统单调时钟。
否则同一帧里触发的图标重读，它的 `capturedAt`（读取开始的真实时刻）会比这一帧的时间还早，
交互感知就会误以为"这是松手之前读的"，迟迟下不了结论。

`FrameTime.now()` 只应由"产生帧"的一方调用（叠加层、演示程序的主循环）。
`time.advanced(by:)` 往后推若干秒，写测试、编剧本用。

文档里凡是说"时刻""单调时钟"的 `TimeInterval`（`capturedAt`、`startedAt`、`releasedAt`、`.by(t)` 里的 t），都是 `monotonic` 这个时基。

### 10.2 `FrameDemand`——省电信号

"我什么时候需要被再次调用"。

| 值 | 含义 |
|---|---|
| `.continuous` | 有动画或连续变化正在进行：每个显示刷新都要一帧 |
| `.by(t)` | 当前没有动画，但最晚在 t 时刻要再算一次（下一次眨眼、下一次读鼠标）。t 已经过去则视为立刻。也可以用来表示"有动画，但不必每个显示刷新都算"——例如眨眼途中、慢慢消退的余韵，情绪引擎给的是 `.by(现在 + 1/30 秒)`：醒晚一点不会出错，只是那一小段动画粗一点 |
| `.idle` | 没有任何定时需求；只在外部事件（图标变化、`requestFrame()`）到来时再算 |

`a.merged(with: b)` 取两者里更紧的。应用把交互感知的、情绪引擎的合起来；每张脸的循环小动画（`animationInterval`）也折算进来——间隔为 0 算 `.continuous`，正数算 `.by(下次刷新的时刻)`；
结果放进 `OverlayFrame.demand` 交给叠加层。

**这是全应用省电的核心**：没事的时候每个模块都应如实报告"没事"。常见情形——

| 情形 | 交互感知 | 情绪引擎 | 结果 |
|---|---|---|---|
| 鼠标在动 | `.continuous` | `.continuous`（眼睛在转） | 连续出帧 |
| 鼠标停住，没人眨眼 | `.by(稍后)`（低频读鼠标） | `.by(下次眨眼)` | 每秒醒几次 |
| 鼠标停住，有图标在打瞌睡 | `.by(稍后)` | `.by(下次眨眼)` | 按表情模块给的间隔（如每秒 10 次）只重画睡着的那几张 |
| 暂停 / 桌面看不见 | 不被调用 | 不被调用 | 完全不出帧 |

### 10.3 `SeededRandom`——可复现的随机数

逻辑模块不得使用全局随机数（`Double.random(in:)` 的无参形式、`SystemRandomNumberGenerator`）。种子由外部传入。

- `SeededRandom(seed:)`：符合标准库的 `RandomNumberGenerator`，可以直接用在 `Double.random(in:using:)`、`shuffled(using:)` 等接口上。算法是 SplitMix64，跨平台结果一致。
- `nextUnit()`：下一个 [0, 1) 的小数。
- `SeededRandom.mix(_:)`：把一个数打散成毫不相关的另一个数（无状态）。
- `SeededRandom.derive(seed, stream:)`：由一个种子派生出第几路互不相关的子种子。例如同一个长相种子，表情模块用第 0 路定眼距，情绪模块用第 1 路定性格——各取各的，互不影响。

### 10.4 示例

```swift
// 应用把各模块的需求合成一个，交给叠加层。
let fromSensor = FrameDemand.by(time.monotonic + 0.1)     // 鼠标没动：0.1 秒后再读一次
let fromDirector = FrameDemand.by(time.monotonic + 2.5)   // 2.5 秒后有人要眨眼
fromSensor.merged(with: fromDirector)                     // .by(time.monotonic + 0.1)
fromSensor.merged(with: .continuous)                      // .continuous

// 随机数：种子由外部传入，同样的种子永远得到同样的结果。
var rng = SeededRandom(seed: 42)
let nextBlinkIn = Double.random(in: 2...6, using: &rng)

// 由长相种子派生互不相关的"子种子"。
let seed = IconID(rawValue: 7).faceSeed
let eyeSpacingSeed = SeededRandom.derive(seed, stream: 0)
let personalitySeed = SeededRandom.derive(seed, stream: 1)
```

## 12. 留的余地，以及接口不够用时

### 12.1 为尚未验证的事留的余地

| 不确定的事 | 接口怎么留余地 |
|---|---|
| 访达 desktop position 的锚点是图标中心还是左上角 | 接口只暴露算好的 `imageRect`；锚点和推算公式完全是图标桥内部的事，改了不影响任何人 |
| 手动拖动后访达报告的位置是否即时更新、延迟多久 | `ReleasedDrag` 表达"已松手、结局未定"的中间状态；`wantsIconRefresh` 可以连续多帧请求重读；`capturedAt` 让交互感知知道快照是不是松手之后读的；结局里有 `.unknown`（超时） |
| 废纸篓的精确位置 | `TrashInfo` 只承诺"估算区域 + 可信度"；情绪规则应当对位置偏差不敏感。是否真的进了废纸篓不靠位置判断，靠 `DragOutcome` / `DeletionEvent` |
| 消失的图标到底去了哪 | `TrashVerdict` 有 `unknown` |
| 标签矩形读不读得到 | `labelRect` 可空；`hitTest` 在没有标签时退化为只认图像矩形 |
| 首次授权弹窗的表现 | 弹窗等待期间状态是 `starting`；拒绝后是 `permissionDenied`；两种状态下快照都是空的，应用什么都不画 |
| 图标所在显示器、修改时间 | 都是可空字段 |

### 12.2 接口不够用时

各子对话**不要自己改 `Sources/DDMCore/` 和 `Package.swift`**。发现接口缺东西、有歧义或者不合理：

1. 把"需要什么、为什么、建议怎么改"写进回报；
2. 如果因此卡住无法继续，给总览发一条简短消息；
3. 由总览统一修改 DDMCore，并通知受影响的模块。

能在模块内部解决的（内部辅助类型、内部协议、私有扩展）不需要走这个流程。

### 12.3 Windows 版的预定约定（还没有实现）

Windows 版目前只有调研方案（`docs/windows/移植方案.md`）。方案 §1.1 提出的接口问题，总览定下的方向如下；真正开工时再改 DDMCore，
macOS 版现在一行都不用动。

| 问题 | 定下的方向 | 理由 |
|---|---|---|
| 坐标单位 | **Windows 上 1 点 = 1 物理像素，每块屏的 `scale` 都是 1。** 情绪引擎、交互感知里以点为单位的手感常数（起拖距离、甩动分段、`fearRadius`、`waveSpeed` 等），在构造时按主屏的缩放比例换算后传入（两个模块的调参表本来就能在构造时给）；逻辑代码不改 | 系统给的所有坐标都不用换算；混合缩放的多屏没有标准的"点"平面可拼。代价是副屏缩放与主屏不同时手感略有差别 |
| 标出回收站 | **`IconSnapshot` 加一个可空字段"回收站是哪个图标"**；macOS 版恒为空 | 不往 `IconKind` 里加种类：那样各模块里按种类分情况的代码都要跟着改；加一个可空字段，macOS 各模块一行不用改 |
| 图标被系统隐藏 | 与 macOS 一致：图标桥不管，由叠加层的 `isDesktopVisible` 负责 | 同一个概念，两边同一种处理 |
| 图标被桌面整理软件接管 | 倾向于复用 `stacksEnabled`，含义放宽为"图标位置不可信"；等上机验证（V22）的结果再定 | 两种情况的后果相同：位置不能用来画脸 |
| `permissionDenied` | Windows 上不用；向资源管理器调用被拒归 `finderUnavailable` | Windows 上没有"用户拒绝授权"这回事 |
| `DesktopAppearance`、谁去找桌面窗口 | 照方案 §1.1 第 5、6 条办，不改接口。向资源管理器发调用的只有图标桥一家 | 与 macOS 版"只有图标桥问访达"的约定一致 |
