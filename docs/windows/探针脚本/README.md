# 探针脚本

> **未经运行。** 这个文件夹里的所有脚本都是在一台 Mac 上写的，没有在任何 Windows 电脑上运行过、也没有编译过，只做过人工通读和一次独立审阅。
> 它们的用途是把 [../移植方案.md](../移植方案.md) 里"未经实测"的关键结论拿到真机上核对；每个脚本对应 [../上机验证清单.md](../上机验证清单.md) 里的若干项。
> 第一次运行如果报错，报错本身就是有用的信息，请原样交给负责 Windows 版的人。

## 怎么运行

需要：Windows 10 或 11。**不用安装任何东西**——脚本用系统自带的 Windows PowerShell 5.1 和系统自带的 .NET Framework。

1. 把整个 `探针脚本` 文件夹拷到 Windows 电脑上（任意位置）。
2. 在这个文件夹的空白处按住 Shift 点右键 →「在此处打开 PowerShell 窗口」（Windows 11 是「在终端中打开」）。
3. 逐条运行，例如：

```
powershell -NoProfile -STA -ExecutionPolicy Bypass -File .\01-read-icons.ps1
```

说明：

- `-ExecutionPolicy Bypass` 只对这一次运行放行脚本，不改系统设置。
- `-STA` 是这些脚本访问资源管理器、开窗口所必需的。
- 请用 `powershell`（5.1），不要用 `pwsh`（PowerShell 7）——内嵌的 C# 是按 5.1 自带的编译器写的。
- 不要"以管理员身份运行"。
- **怎么提前结束**：01、05、06、07、08 按 Ctrl+C 即可。**02、03、04 运行时 Ctrl+C 不起作用**（PowerShell 要等里面那一大步做完才响应），
  请直接按 **Esc**；如果之前点过别处，先用 Alt+Tab 切回这个 PowerShell 窗口再按。实在不行，直接关掉这个 PowerShell 窗口。
- **出错时**：脚本只打印出错的文件名、行号和错误说明（不打印含用户名的完整路径）；内嵌的 C# 编译失败时，只打印 `common.ps1` 里的行号和编译器的说明。
- 文件是带 BOM（字节顺序标记）的 UTF-8 编码，Windows PowerShell 5.1 靠它识别中文。请不要用会去掉 BOM 的编辑器转存。
- 中文显示成乱码或方框时：换到 Windows 终端（Windows Terminal）里运行。要交回输出，**直接在窗口里选中文字复制**最稳妥；
  重定向到文件（`> 输出.txt`）的办法在这种环境下可能得到乱码，不推荐。
- 脚本会把这个窗口的输出编码改成 UTF-8，跑完关掉这个窗口即可恢复，不影响别的窗口。
- 杀毒软件可能对"脚本里编译并调用系统接口"起疑。脚本做的事都写在各自的开头，可以先读再跑。

## 这些脚本做什么、不做什么

**做**：经系统公开的接口向资源管理器询问桌面图标的位置、大小、种类；读鼠标位置和按键状态；问"某个点上是哪个窗口"；
开一个透明、不抢焦点的窗口画几个框（除了 03 的 `-NoRedirectionBitmap` 模式，都点击穿透）。

**不做**：不注入、不读写别的进程的内存、不装钩子、不改任何系统设置、不移动或改名任何图标、不读取你的任何文件的内容、不联网、不留下任何常驻的东西。

**不输出你的文件名**：图标只以"序号 + 种类 + 位置"出现。窗口只打印类名和归属（本进程 / 资源管理器 / 另一个 PowerShell / 别的程序），不打印标题。

**会写文件的地方**：
- `05-recycle-bin.ps1` 在桌面上新建一个名字以「别删我-测试-」开头的临时文本文件，让你拿它做实验；结束时它还在桌面上就删掉。
  运行前请先关掉桌面的"自动排列图标"，否则新建和删除它时别的图标会跟着重新排位。
- `06-file-times.ps1` 在系统临时文件夹里新建一个小文件，改一下它自己的访问时间、读一下它，然后删掉。
- 每个脚本在编译内嵌的 C# 时，系统会在临时文件夹里写下并删掉几个编译用的临时文件。

除此之外不碰任何文件。

## 拿到结果之后

每一项的"预期结果"和"如果不成立怎么办"都在 [../上机验证清单.md](../上机验证清单.md) 里。
脚本本身如果有毛病（编译不过、接口调用失败），最可能出错的地方：

| 现象 | 最可能的原因 | 去哪改 |
|---|---|---|
| `Add-Type` 报一串编译错误 | 内嵌 C# 的笔误 | `common.ps1` 里的 C# 源码 |
| "FindWindowSW 没有找到桌面"，或这一步抛出异常 | 资源管理器没在运行；或者 `IShellWindows` 的方法次序声明错了（主路径按虚表调用，失败后会自动改为按名字调用，两条都失败才报错） | `common.ps1` 里的 `IShellWindows` 声明和 `DesktopView.FindDesktopDispatch` |
| 读图标时进程崩溃或返回一堆乱数 | 某个接口的方法次序声明错了 | `common.ps1` 里 `IShellBrowser` / `IShellView` / `IFolderView` / `IFolderView2` 的声明 |
| "视图标志""图标边长"和"Shell 视图脚本对象的读数"两行对不上 | `IFolderView2` 的方法次序声明错了（以脚本对象那一行为准） | 同上 |
| 所有图标的"屏幕位置"整体偏了一截 | 位置不是相对列表窗口的；或缩放感知没生效 | `DesktopView.ReadIcons` 里换算坐标的那两行 |
| 03 开头的"实际属主"在 `-Mode owner` 下不是 `Progman` / `WorkerW` | 属主没改成功 | `OverlayForm.ApplyOwner` |
| 03 开头写着"窗口被系统截小了" | 窗口大小被系统限制在一个上限里，副屏的一部分没有框 | `OverlayForm` 的构造函数（改成每块屏一个窗口） |
