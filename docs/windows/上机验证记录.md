# Windows 上机验证记录

> 由总览整理。按 [上机验证清单.md](上机验证清单.md) 的编号记录**实际跑出来的结果**；方案里的推断以这里为准修正。
> 探针脚本没有改动，用的就是 `探针脚本/` 里的版本。

## 环境

| 项目 | 情况 |
|---|---|
| 宿主 | Apple M5 的 Mac，macOS 27.0.1 |
| 虚拟机 | UTM（免费开源版），虚拟化（不是模拟），8 GB 内存、4 核、64 GiB 硬盘 |
| Windows | Windows 11 ARM64 简体中文，版本 10.0.26300（来自微软给 ARM 电脑的安装镜像；未激活） |
| 显示 | 一块虚拟显示器，1512×949，缩放 100%（96 DPI） |
| 桌面 | 3 个图标：回收站、"了解此图片"（系统图标）、Microsoft Edge（快捷方式）；对齐网格开、自动排列关 |
| 运行方式 | 脚本放在 UTM 的共享文件夹（Windows 里是 Z: 盘）；终端是以管理员身份打开的（探针 README 建议普通权限，这几项都是只读的，推断不受影响，之后用普通权限复跑确认） |
| 时间 | 2026-11-13 晚至 11-14 中午，用户亲手操作 |

## 第一组（V01–V05）

| 编号 | 结论 | 关键数据 |
|---|---|---|
| **V01 读得到图标** | **通过** | 经资源管理器的桌面视图接口（`IFolderView2`）读出 3 个图标的位置和种类，读取失败 0 个；**回收站认出来了**（种类"回收站"）；格子 78×98（叠加窗口那次读到 75×98），图标边长 48；快捷方式读到了修改时间，回收站和系统图标没有修改时间 |
| **V02 位置含义与叠加窗口** | **通过** | **绿框（把读到的位置当作"图标图像的左上角"）正好套住图标图像**；红框（当作格子左上角、图像居中）偏右。橙框（文字矩形估算）大致框住名字。用户确认：在框上单击、右键、拖选框都和平时一样（点击穿透）；普通窗口能盖住框。窗口样式 `LAYERED | TRANSPARENT | NOACTIVATE | TOOLWINDOW` |
| **V03 拖动期间读取** | **通过，比 macOS 省心** | 40 秒 922 次读取，平均 2.4 毫秒、最长 81 毫秒；三次真实拖动（按住 3.3 / 1.3 / 11.9 秒）期间**读取都没有卡顿**；拖动途中位置不变；**松手后 8～31 毫秒读到新位置**。因为开着"对齐网格"，图标落点按格子取整（纵向位移 196、294 = 2、3 个格子高），和鼠标位移差得多。拖出去又拖回原位的三次，正确地判为位置没变 |
| **V04 显示桌面（Win+D）** | **属主法通过；沉底 + 上浮不稳** | `-Mode owner`：实际属主 `Progman`；Win+D、点任务栏末端、打开资源管理器窗口全程，每一行都是"叠加窗口在桌面窗口之上"，普通窗口照常盖在它上面；**用户肉眼：框一直在、没有闪**。`-Mode follow`：Win+D 后每秒多次上浮，但每 2 秒的状态多数仍是"被桌面盖住了"；**用户肉眼：框时有时无**。→ 按清单：**以属主法为 Windows 叠加层的主方案**；还要做 V19（属主法下重启资源管理器能否重建）。属主法下桌面会不会变迟钝，用户没有反映，之后留意 |
| **V05 命中判断与起拖阈值** | **基本通过** | 系统起拖阈值 4 / 4 像素（100% 缩放）。鼠标在桌面空白处、图标上 → "桌面图标层（SysListView32 ← SHELLDLL_DefView ← 顶层 Progman）"；普通窗口上 → "别的程序的窗口"或资源管理器窗口；任务栏 → `Shell_TrayWnd`。单击、按住不动 → "没有越过阈值，算点击"；在窗口标题栏上拖 → 判为拖拽但按下处不是桌面（正确）。**未完成**：在图标上慢慢拖的那一次，越过阈值时 40 秒到了，没记到松手；"拖影出现"和"越过阈值"是否同时，没有确认；带着叠加窗口再跑一遍（确认不出现"本进程的窗口"）也没做 |

## 对方案的影响

- **读图标**（方案 §2）：主路线成立。图标图像矩形 = 读到的位置为左上角、边长 = 读到的图标边长（100% 缩放下）。别的缩放比例下边长要不要乘缩放，等 V10。
- **拖动期间**（方案 §2.9）：Windows 上资源管理器拖动期间照常回应，**不需要** macOS 版那套"访达一时没空"的处理；仍保留"超时不等于不可用"。
- **叠加层**（方案 §3.2、§3.3）：主方案改为**属主法**（叠加窗口的属主设为桌面窗口），不是"沉底 + 发现被盖住就上浮"。原列为第一风险的问题在这台机器上有解。
- **交互感知**（方案 §4）：用"这个点上是哪个窗口"认桌面图标层的办法成立；起拖阈值读系统参数。
