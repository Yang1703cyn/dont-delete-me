# 演示动图分镜

> **归属** release。这份文档只是拍摄方案，**还没有实际录制**。
> 文中的时间点依据 `docs/模块说明/emotion.md` §3.3 的默认节奏推算（脸红约 0.5 秒到顶、幽灵全程 2.6 秒、围观在离废纸篓约 290 点时开始等），
> 实拍时以画面为准，前后差一两百毫秒没有关系。

## 0. 一眼看懂的标准

动图里不放任何字幕。观众只看画面，要能自己说出这三件事：

1. **图标长了脸，眼睛在跟着鼠标转。**
2. **往废纸篓拖，它会越来越怕，最后大哭；旁边的图标不敢看。**
3. **真删了，会飘出一个小幽灵。**

三件事对应三个节拍：**看 → 怕 → 鬼**。主动图三拍都有；短版只留后两拍。

录完之后的检验办法：找一个没听说过这个项目的人，不给任何说明看两遍，请对方说说"这个软件是干什么的"。说不出第 2 条，就重录。

## 1. 画面与布局

- **只录屏幕的一块**，大约 880 × 550 点（16:10），右下角包住废纸篓。不录菜单栏。
- **图标调大**：桌面图标大小调到 96（访达 → 显示 → 查看显示选项；应用支持 32～128）。默认的 64 在缩小后的动图里脸太小。
- **8 个图标**，其中 1 个在睡觉。摆法如下——主角到废纸篓之间是一条空着的斜线，拖的时候不会经过别的图标
  （经过文件夹上方会让访达把它高亮成"放进这个文件夹"，既抢戏，又有误放的风险）：

```
┌──────────────────────────────────────────────────────┐
│  [围观1]  [围观2]  [围观3]  [围观4]         [睡着的]   │
│                                                      │
│  [围观5]  [围观6]                                     │
│                                                      │
│                  [主角]                               │
│                        ╲   （这条斜线上不放图标，        │
│                          ╲   约 450～500 点长）        │
│                            ╲     ┌───────────┬─────┐ │
│                              ╲___│ 程序坞右端  │废纸篓│ │
└──────────────────────────────────┴───────────┴─────┘─┘
```

- **睡着的图标放在右上角，远离鼠标要走的路线**：鼠标在它 90 点以内移动会把它吵醒，开场就看不到"有一个在睡觉"了。

- **主角离废纸篓 450～500 点**：害怕是从 450 点左右开始的，起点够远，才能拍到"从平静到大哭"的完整过程。
- **墙纸**用系统默认的，或者一张干净的浅色纯色图。不要用自己的照片。

## 2. 主动图（9.6 秒，不超过 10 秒）

| 时间（秒） | 鼠标在做什么 | 画面里发生什么 | 观众读到什么 |
|---|---|---|---|
| 0.0 – 1.2 | 从画面右侧的中部进来，向左滑到主角旁边（走画面中间那条空着的横带，离右上角睡着的图标远一些） | 所有醒着的图标眼珠跟着鼠标从右转到左（碰巧有谁眨一下眼更好，不强求）。右上角睡着的那个闭着眼、冒 Zzz，不为所动 | 图标有脸，在看我的鼠标；有一个在睡觉 |
| 1.2 – 2.2 | 停在主角「别删我」上，不动 | 主角脸红（约半秒到顶），眼神躲到一边 | 它知道我在看它 |
| 2.2 – 2.6 | 按下，把主角拖起来 | 主角的脸跟着被拖的图标走；其它图标一齐转头盯着它 | 要出事了 |
| 2.6 – 5.4 | **慢慢地**朝右下方的废纸篓拖，全程约 2.8 秒，中途不停顿 | 依次出现：瞳孔缩小、长出八字眉 → 冒汗 → 整张脸发抖 → 靠近废纸篓时眼泪涌出来。拖出不到一半（离废纸篓还有约 290 点）时，围观从离主角最近的图标开始、像波纹一样传开：有的两手捂眼，有的从指缝里偷看，有的瞪大眼睛；睡着的那个也被惊醒 | 越靠近越害怕；别的图标不敢看 |
| 5.4 – 6.0 | 悬在废纸篓正上方，停半秒 | 主角哭到最凶：眼泪直流、张嘴哭嚎。**这半秒是整条动图的"海报帧"** | 它在求你别删 |
| 6.0 – 6.2 | 松手 | 图标掉进废纸篓，脸消失 | 真删了 |
| 6.2 – 8.8 | 鼠标留在废纸篓附近不动 | 主角**原来的位置**（画面中部）飘起一个白色小幽灵，左右轻轻摇摆着往上升，最后淡出。围观的图标约 1 秒内放下手，全体目送幽灵 | 被删的图标变成了小幽灵 |
| 8.8 – 9.6 | 向画面中间轻轻移一下 | 幽灵散尽，大家的眼睛转回鼠标。停在这个平静的画面上 | 一切照旧（少了一个） |

**循环点**：最后一帧比第一帧少了主角，循环时它会"复活"——读起来像"再来一次"，可以接受。不必为了循环严丝合缝去做处理。

**拍的时候容易出的岔子**

- 拖得太快：汗、发抖、哭叠在一起，看不出层次。2.6–5.4 这一段宁慢勿快，手要稳，走直线。
- 拖得太猛或来回晃：会触发"头晕"，把害怕的戏盖掉（害怕到一定程度后头晕才会让位）。
- 松手位置不在废纸篓上：成了"虚惊一场"，没有幽灵。松手前确认废纸篓已经高亮。
- 幽灵是从**原位置**冒出来的，不是从废纸篓。所以 6.2 秒之后鼠标留在废纸篓那边，别挡住主角原来的位置。

## 3. 短版（4.8 秒，不超过 5 秒）

从"已经抓着主角"开始，只讲**怕 → 鬼**两拍。建议单独录一条（拖得比主动图快一些），不要从主动图里硬剪。

| 时间（秒） | 鼠标在做什么 | 画面里发生什么 |
|---|---|---|
| 0.0 – 0.4 | 已经抓着主角，在起点停一下 | 主角平静地看着前方；其它图标都盯着它 |
| 0.4 – 2.6 | 朝废纸篓拖，约 2.2 秒 | 冒汗 → 发抖 → 流泪；围观的图标由近到远捂眼、偷看、瞪眼 |
| 2.6 – 3.0 | 悬在废纸篓上方 | 大哭（海报帧） |
| 3.0 – 3.2 | 松手 | 图标进了废纸篓，脸消失 |
| 3.2 – 4.8 | 不动 | 原位置飘起小幽灵，升到一半多；大家目送。在幽灵最清楚的时候结束 |

短版适合放在发布说明、社交平台的预览里；README 顶部用主动图。

## 4. 演示用的假文件

全部是**新建的空文件和空文件夹**，名字本身就是包袱。中文、英文各一套，录哪种语言的动图就用哪一套。

| 角色 | 中文版 | 英文版 | 说明 |
|---|---|---|---|
| **主角**（被拖走的） | `别删我.txt` | `dont_delete_me.txt` | 产品名自己出镜，不用字幕也知道这东西叫什么 |
| 围观 | `最终版.txt` | `final.txt` | |
| 围观 | `最终版（真的最终版）.txt` | `final_FINAL.txt` | |
| 围观 | `最终版-打死不改了.txt` | `final_FINAL_v2.txt` | |
| 围观（文件夹） | `新建文件夹 (7)` | `New Folder (7)` | |
| 围观（文件夹） | `明天一定整理` | `sort_this_tomorrow` | |
| 围观 | `别点开.zip` | `do_not_open.zip` | |
| **睡着的** | `健身计划 2021.pdf` | `gym_plan_2021.pdf` | 修改时间设到半年以前，它就会打瞌睡——"健身计划在睡大觉"，名字和状态互相成全 |

备选的名字（想多放几个图标时用）：`重要！！！.txt`、`临时-用完就删.txt`、`毕业论文_v37.txt`、`老板说要大气一点.txt`；
英文：`IMPORTANT!!!.txt`、`temp_delete_later.txt`、`thesis_v37.txt`。

**注意**

- 名字别太长：桌面上放不下的名字会被访达截断或折行，包袱就没了。
- 同时睡着的图标最多占总数的三分之一（8 个图标最多睡 2 个）。想多一个睡着的，给另一个文件也设成很早的修改时间。
- 图标按扩展名显示成什么样子取决于那台机器（没有逐一验证过），摆好之后看一眼；不合适就换扩展名。不要用图片文件：缩略图会被眼睛盖住。
- 谁胆小、谁好奇、谁胆大是按图标固定分配的，没法指定。**先排练一次"虚惊一场"**（拖到废纸篓旁边再放回原处，什么都不会被删），
  看清谁捂眼、谁偷看、谁瞪眼，再调整摆放，让三种反应都落在画面里显眼的位置。

**创建命令**（在演示用的账户里、打开"终端"执行；只新建东西，不碰任何已有的文件。命令已在临时目录里试过）：

```bash
cd ~/Desktop
mkdir "新建文件夹 (7)" "明天一定整理"
touch "别删我.txt" "最终版.txt" "最终版（真的最终版）.txt" "最终版-打死不改了.txt" "别点开.zip"
touch -t 202101010900 "健身计划 2021.pdf"     # 修改时间设成 2021 年 1 月 1 日
```

英文版：

```bash
cd ~/Desktop
mkdir "New Folder (7)" "sort_this_tomorrow"
touch "dont_delete_me.txt" "final.txt" "final_FINAL.txt" "final_FINAL_v2.txt" "do_not_open.zip"
touch -t 202101010900 "gym_plan_2021.pdf"
```

录完之后，这些假文件请在访达里**亲手**拖进废纸篓（顺便再看一遍幽灵）。不提供批量删除的命令，免得在错误的文件夹里执行。

## 5. 怎样避免拍到真实的文件名

按推荐程度排列。

**办法一（推荐）：新建一个专门用来演示的系统用户账户。**
在"系统设置 → 用户与群组"里添加一个新用户，登录进去录。那里的桌面是空的，程序坞、菜单栏、墙纸都是出厂状态，没有任何个人信息可拍。
代价是要在新账户里重新打开一次应用、重新允许它控制访达——正好可以顺手把 README 里几处"待核实"的首次打开步骤和截图补上。录完可以把这个账户整个删掉。

**办法二：只录一小块，把假文件摆在真实桌面的空角落里。**
不动任何真实文件。在靠近废纸篓的一块空地上摆好假文件，录制区域只框这一块。
要点：录之前把选框的四条边都看一遍，确认没有真实图标或它的名字被框进来一半；框里的那段程序坞上有没有不想露出的应用；
画面外的真实图标同样会有反应，但不会被拍到。

**办法三：换一台干净的机器或虚拟机。**
同样干净，但应用目前只在 macOS 27.0.1（Apple Silicon）上运行过，别的环境能不能正常工作不确定；虚拟机里的流畅度也可能不够。

**办法四（兜底）：后期裁剪或打码。**
只在前三种都做不到时用。打码容易漏帧，裁剪更可靠。

**不建议：为了录制把真实文件临时挪走。** 桌面图标的摆放位置挪回来之后未必还原，而且"为了演示去动用户的文件"正好和这个项目的原则相反。

**不管用哪种办法，发布前都要逐帧过一遍**（把动图拖进浏览器或预览逐帧看），重点看：

- [ ] 画面里每一个文件名都是假文件清单里的
- [ ] 程序坞入镜的那一段没有不想露出的应用、最近使用的项目、下载文件夹的内容
- [ ] 没有菜单栏（账户名、时钟、各种状态图标）
- [ ] 没有通知横幅（录之前打开"勿扰模式"）
- [ ] 没有桌面小组件（它们还会把脸盖住）
- [ ] 没有外接磁盘的图标和名字
- [ ] 墙纸不是个人照片

## 6. 录制前的准备清单

- [ ] 桌面没有开"叠放"（开了就没有脸）；"在桌面上显示项目"是打开的
- [ ] 桌面图标大小 96，假文件按第 1 节的布局摆好：主角离废纸篓 450～500 点，斜线上没有图标，睡着的在右上角
- [ ] 程序坞在屏幕底部、不自动隐藏（废纸篓要一直在画面里）
- [ ] 应用在运行、没有暂停；录制区域内没有别的窗口
- [ ] **先真删一次别的假文件**：应用对废纸篓位置的估计，在真的删过一次之后会自动校准，之后的反应更准
- [ ] 排练一次"虚惊一场"，确认三种围观反应都在画面里
- [ ] 每拍完一条，在访达里用"撤销"或废纸篓里的"放回原处"把主角请回来；位置变了就摆回去

## 7. 录制与导出

- **录制**：用系统自带的截屏工具（按 Shift-Command-5，选"录制所选部分"），得到一个 .mov 视频。
- **转成动图**需要第三方工具（例如 ffmpeg 或 gifski）。**这台开发机上两样都没有装，下面的命令是常见写法，没有在本机运行过**，用之前请先试一条短的：

  ```bash
  ffmpeg -i demo.mov -vf "fps=15,scale=800:-1:flags=lanczos,palettegen" palette.png
  ffmpeg -i demo.mov -i palette.png -lavfi "fps=15,scale=800:-1:flags=lanczos[x];[x][1:v]paletteuse" demo.gif
  ```

- **建议的规格**（经验值，不是硬性限制）：宽 720～800 像素；每秒 15 帧；主动图尽量在 5 MB 以内，最多不超过 10 MB，否则 README 打开会慢。
  太大时先降帧率到 12，再缩小宽度，最后才考虑减少颜色。
- **存放位置（待定，需总览确认）**：建议 `Assets/demo.gif`（主动图）和 `Assets/demo-short.gif`（短版）。README 顶部的占位注释里已经按这个路径写好了。
- **语言**：文件名会入镜。最省事的做法是只录英文版一条，中英文 README 共用；有余力再用中文假文件录一条给中文 README。这一点需要用户决定。
